# 问答检索首页

用户最新决定覆盖此前“全局技能列表作为默认首页”：`/` 使用 OpenDesign HomeHero 的居中问答框；`/library` 独立承担全局技能浏览与维护。来源已经明确为本应用当前中央技能目录，不再存在待确认的“仓库地址”概念。

## 来源与产品流程

首页读取后端 `central_repo::skills_dir()`，遵循应用已有目录设置及隔离环境覆盖。默认通常为 `~/.skillharbor/skills`，实际以首页显示的绝对路径为准。首页不选择或克隆 Git 仓库，不搜索项目源码，也不联查公开技能市场。市场及 Git 导入继续属于独立的发现/安装功能。

流程为：中文提问 → 当前中央目录的真实混合检索 → 立即展示命中片段与来源 → 通过已有 CLI 整理中文回答 → 阅读技能 `/library?skill=…` → 软链接加入项目。全局源文件统一维护、项目只管理引用的产品不变量不变。

## 独立索引管理

索引构建是独立功能，固定路由 `/search-index`，侧栏、快捷查找及首页状态区均有入口。建立、更新、重新检查、目录、模型及失败重试集中在该页。首页只展示简洁状态和“管理索引”链接。构建状态由应用共享，切换页面不丢失任务；构建过程不依赖问答或 Codex CLI。

## 布局与状态

- 以源项目 HomeHero 的居中输入区为依据：身份标识、中文标题、问答输入区、底部操作栏及当前目录。保留公共壳层与全页点阵，不复制页面级鼠标监听。
- **输入区（composer）复刻标准**（源：`home-hero.css:507-624`、`composer-beam.css`、`HomeHero.tsx:422-485/1631-1645/2300-2336`）：
  - **托盘**：无边框中性灰托盘（`--ds-subtle`），radius 20px，padding 4px（底部 8px）；分组靠底色而非描边，无阴影。
  - **白色内卡**：radius 16px（与托盘同心：20 = 16 + 4px 内边距），idle 无边框（1px 透明），`--ds-bg` 白底；`:focus-within` 时浮现最浅灰描边（`--ds-border-soft`）。label、textarea、操作行都在内卡中；当前目录行是托盘底部裸文本行（对应上游 workdir-row）。
  - **聚焦光束**：绿（#00ff08）→青（#00fbff）的 280px 光斑沿内卡**边框**绕行（8s 一圈）；聚焦 0.6s 淡入、失焦 0.5s 淡出后卸载。机制：border-box XOR padding-box 的环形 mask + `offset-path`（由 JS ResizeObserver 测量写入 `--beam-path`）；相位状态机 idle→active→fading→idle，失焦用 relatedTarget 包含检查忽略卡片内部焦点移动；`prefers-reduced-motion` 下整体隐藏。
  - **发送按钮**：36×36 近黑（#202020）超椭圆（radius = 36×14/32）+ 绿色箭头；禁用态（未输入）与可用态外观完全一致（不褪色），hover 仅轻微加亮；busy 显示 60 次封顶 spinner；图标按钮必须带 `aria-label`。
  - textarea 打开页面即自动聚焦（autofocus）。
- 普通用户看“建立/更新索引”“目录与索引详情”；依赖实现和模型细节仅在开发文档或展开详情显示。
- 索引检查、尚未就绪、建立中、失败、检索中、无结果、回答中及回答失败分别显示。首次下载明确说明可能需等待，不提供虚构进度。
- 先展示实际命中结果，再异步回答。回答失败不丢弃来源，允许单独重试回答。不能把关键词包含匹配或市场搜索冒充本地混合检索。
- 每条来源显示技能名、原始路径、行号范围与命中片段；阅读/链接操作使用现有公共控件和流程。没有检索时不填示例结果。
- 避免重复提交、忽略过期请求、卸载时失效请求。输入有可见标签，支持按钮和 Cmd/Ctrl+Enter；中文输入法组合态不触发快捷提交。

## 对话入口

composer 操作行另有"技能库上下文"开关（默认开）与副按钮"对话提问"：点击后携带当前输入跳转 `/chat/:id`，用设置页选定的本机 CLI 发起流式多轮对话；开关开启时把本次检索命中片段注入对话 prompt。⌘/Ctrl+Enter 与主按钮仍是上述技能搜索主流程，不受影响。对话功能的设计与实现边界见 [CHAT.md](CHAT.md)。

## 实现与数据边界

`SearchHome.tsx`、同名 CSS Module、`lib/skillSearch.ts` 为前端；后端命令为 `skill_search_status`、`skill_search_index`、`skill_search_query`、`skill_search_answer`。

本地检索运行时固定 `@zvec/zvec-grep@0.2.1`，使用 `local/multilingual-e5-small`（CPU/q8）进行多语言向量嵌入与原生索引混合检索。首次需要从 Hugging Face 下载模型；后续本地嵌入推理不上传技能源内容。具体安装和原生平台约束见 [search-runtime README](../../search-runtime/README.md)。

0.2.1 的索引位置绑定工作区根目录，因此适配层只读中央目录，将符合条件的 Markdown 文档同步到独立缓存镜像，再在那里建立索引。缓存位于默认应用数据根的 `local-workbench/search/<canonical-root-hash>/`：文档镜像在 `workspace/`，索引在 `workspace/.zvec-grep/`，模型在 `models/`。不会在中央技能源目录创建 `.zvec-grep`，不会改写技能文件。返回路径映射回原始中央目录，缓存中的文档复制不是项目部署。

当前覆盖非隐藏、非软链接 `.md`/`.mdx` 文件，单文件不超过 1 MiB，跳过 `node_modules`。查询前同步新增、修改和删除，原生查询开启自动更新；手动更新索引仍提供明确的用户入口。不能据此声称图片、PDF或任意二进制文件已被检索。

中文回答使用应用已有 Codex CLI 文本生成能力，仍可能调用远程模型；“本地嵌入”不代表回答全过程离线。仅把问题和候选片段提供给回答步骤，不运行找到的技能。CLI 不可用、未登录或生成失败时保留检索结果。回答引用编号对应本次候选顺序，路径/行号是出处展示；候选元数据未在回答命令中独立核验，不能声称所有回答事实都经过自动验证。
